# 三語教學（v1 計劃 5a）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use busdriver:subagent-driven-development (recommended) or busdriver:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把刷機教學改成 Oh I'm Smart 的版本：简中 `README.md`、英文 `README.en.md` 修改，繁中 `README.zh-Hant.md` 新增，三份互相連結；加上 `tools/check-readmes.sh`，三份的指令和網址不一致就報錯（spec §7.1、§7.3、§5.4、§5.5）。

**範圍：** v1 計劃 5 分成兩份。**這一份（5a）**只改教學和 spec 的文字，不需要母機。**5b**（映像 Release）是 spec §5.6 的發佈流程：`VERSION` 改為 1.0.0、客戶端和系統層的線上更新 Release、母機準備、擷取和打包（映像計劃 Task 8）、pre-release、驗收；它需要母機的 IP 和維護者的實機操作，另寫計劃。教學裏只有發佈後才知道的數字（映像檔大小、日期）在 5b 補上，這份計劃把它們寫成「見 Release 說明」。

**Architecture:** 简中是上游的主版本，先改它；英文照简中逐節同步（目前落後兩個 commit）；繁中由改好的简中經 OpenCC `s2twp` 轉換，再逐段人工校對，用詞跟介面的繁中翻譯一致（台灣用語：連線、網路、裝置、螢幕）。`tools/check-readmes.sh` 比對三份的指令區塊和網址，由 pytest 測試，也對 repo 裏的三份教學執行。

**Tech Stack:** Markdown、bash、awk、pytest（`uv run --no-project --with pytest`）、`opencc-python-reimplemented`（`uv run --with`，只在轉換時用，不進 repo）。

**Global Constraints:**
- 這是 v1 七份計劃的第 5 份的前半。已完成：映像打包（Task 8 除外）、更新器訊息鍵、客戶端英文、網關英文和網址、kiosk 語言選擇、bootstrap（4a、4b）。
- **保留上游的檔案結構**（spec §7.1）：章節、錨點的次序不變，改動集中、小而清楚，減少日後合併上游的衝突。
- **三份教學的指令必須逐字相同**（比對時忽略註解、空行和 `<…>` 佔位符的寫法）。指令裏讓用戶自己填的值一律寫成 `<…>` 佔位符，各語言用自己的文字；指令會印出的固定文字（例如 `echo` 的提示）三份用同一句英文。內文裏網址中要用戶填的部分也寫成 `<…>`（例如 `http://<代理地址>:<端口>`），否則網址的比對抽不到它。
- 引用畫面上的文字時，各語言引用該語言介面上實際顯示的文字（見「背景」的對照表），不再寫「简中原文（英文翻譯）」。
- 教學不寫任何維護者的資料（IP、主機名稱、WiFi、帳號）。
- 主 repo 的改動在分支 `docs/tutorial` 上，merge 到 `main` 只用 `git merge --no-ff`，不 rebase、不 force-push。測試一律以 `GIT_CONFIG_GLOBAL=/dev/null` 執行，不接 `| tail`。

## 決定

1. **简中是主版本，英文和繁中跟它對齊。** 檢查以 `README.md` 為準，報告另外兩份跟它的差異。
2. **`tools/check-readmes.sh` 比對的內容：**
   - 標記為 `bash`、`sh`、`powershell` 的程式碼區塊（包括清單裏縮排的區塊），依出現次序；去掉整行註解、行尾的 ` # 註解`、空行和行首行尾的空白；`<…>` 裏有小寫英文字母以外的字元（中文、大寫、數字、空白、底線）就當作同一個佔位符，全是小寫字母的（例如 `<title>`）是指令裏的 HTML 標籤，照原樣比對。所以英文的佔位符一律用大寫（`<DATE>`，不是 `<date>`）。沒有標記語言的區塊是預期輸出或流程圖，不比對（「整體流程」那個區塊是各語言的文字）。
   - 所有 `http://`、`https://` 網址的集合，同樣先把 `<…>` 換成同一個佔位符。
   - 每一份都要連到另外兩份（`(README.md)`、`(README.zh-Hant.md)`、`(README.en.md)`）。
   - 不比對內文裏的行內指令：它們跟區塊裏的指令重複，而且夾在句子裏，無法可靠地抽出來。
3. **繁中用台灣用語**，跟介面的繁中翻譯一致。
4. **路線 A 和 bootstrap 的 WiFi 方式標示為實驗性**（spec §7.3）：「實驗性：未經 Oh I'm Smart 在原廠裝置上實測」，標在路線 A 的開頭和 A4 的準備步驟。
5. **`prepare.sh` 是可選的**：A4 先說「只用 USB 的話，直接刷下載的 bootstrap 映像」，再給「想多一條 WiFi 的路」的步驟。要用它需要 Docker 和這個 repo 的 clone（`git` 在 0.2 裝 edl 時已經裝了）。
6. **教學裏指令不變的地方不動。** 只改 spec 要求的內容和英文的同步，不重寫上游的文字。

```bash
#!/bin/bash
# The three tutorials (README.md 简中, README.zh-Hant.md 繁中, README.en.md English) must give the
# same commands and the same web addresses (spec §7.1). Compared: every fenced block tagged bash,
# sh or powershell, after dropping comments and blank lines and treating any <…> placeholder as the
# same word (each language names its placeholders in its own words); and the set of http(s)
# addresses. Untagged blocks hold expected output or prose and are not compared. Each tutorial must
# also link to the other two. Usage: tools/check-readmes.sh [repository directory]
set -euo pipefail
export LC_ALL=C    # byte-wise and present everywhere (C.UTF-8 is not on every macOS)
DIR=${1:-$(cd "$(dirname "$0")/.." && pwd)}
FILES="README.md README.zh-Hant.md README.en.md"
WORK=$(mktemp -d)
trap 'rm -rf "$WORK"' EXIT
fail=0

# Placeholders first, so that http://<设备IP>:16688 and http://<DEVICE_IP>:16688 are one address.
# Only a <…> holding something other than lowercase ASCII letters is a placeholder: a tag such as
# <title> in a command is compared as written.
placeholders() { sed -E 's/<[^<>]*[^a-z<>][^<>]*>/<>/g' "$1"; }

for f in $FILES; do
    [ -f "$DIR/$f" ] || { printf 'check-readmes: %s is missing\n' "$f" >&2; exit 1; }
    placeholders "$DIR/$f" | awk '
        /^[[:space:]]*```(bash|sh|powershell)[[:space:]]*$/ { inside = 1; n++; print "--- block " n; next }
        /^[[:space:]]*```/ { inside = 0; next }
        inside {
            sub(/^[[:space:]]+/, "")
            if ($0 ~ /^#/) next                       # a comment line
            # shortcut: " # " inside quotes is taken as a comment too; no tutorial command has one
            sub(/[[:space:]]+#[[:space:]].*$/, "")    # a comment after the command
            sub(/[[:space:]]+$/, "")
            if ($0 != "") print
        }' >"$WORK/$f.commands"
    placeholders "$DIR/$f" | grep -oE 'https?://[-A-Za-z0-9._~:/?#@!$&*+,;=%<>]+' |
        sed -E 's/[.,;:]+$//' | sort -u >"$WORK/$f.urls" || true
    for other in $FILES; do
        [ "$other" = "$f" ] || grep -qF "($other)" "$DIR/$f" || {
            printf 'check-readmes: %s does not link to %s\n' "$f" "$other" >&2
            fail=1
        }
    done
done

for f in README.zh-Hant.md README.en.md; do
    for kind in commands urls; do
        if ! diff -u --label "README.md ($kind)" --label "$f ($kind)" \
            "$WORK/README.md.$kind" "$WORK/$f.$kind" >"$WORK/diff"; then
            printf 'check-readmes: the %s of %s differ from README.md:\n' "$kind" "$f" >&2
            cat "$WORK/diff" >&2
            fail=1
        fi
    done
done
[ $fail -eq 0 ] && printf 'check-readmes: the three tutorials agree\n'
exit $fail
```

**偏離計劃的地方：**

1. **Task 1 故意破壞的第三項**照第 4 輪審閱的意見做：把 `^[[:space:]]*` 換成 `^`，不是刪掉（刪掉之後樣式沒有錨點，仍然認得縮排的區塊，測試不會失敗）。三項破壞都讓對應的測試失敗。
2. **佔位符的規則（Litmus 兩輪）：** 原本的 `sed` 規則會把重導向當成佔位符：`cat < a.img > b.img` 和 `cat <a.img>b.img` 換掉檔名後仍然算相同。改用 `perl`（macOS、Linux 都內建）：佔位符頭尾不能是空白，裏面不能有 `.` 或 `/`，而且要有小寫英文字母以外的字元。加了 `test_redirections_are_not_placeholders`（三種寫法），先確認三個都在舊規則下失敗。所以測試是 12 個，不是 9 個。同一輪也把網址那條管道的 `|| true` 移到 `grep` 上（其他步驟失敗仍會停下），測試改用 `[[ ]]`。已知限制以 `shortcut:` 註解寫在腳本裏：`cat <IN>out` 仍會被當成佔位符，教學裏沒有這種寫法。
3. **一個 commit 超過 Litmus 的大小上限**（約 1500 行，主要是新的繁中檔）。照計劃一起 commit，以 `LITMUS_MAX_WEIGHTED_LINES=2000 LITMUS_MAX_TOTAL_LINES=2500` 執行審閱，沒有跳過。
4. **繁中的錨點**不是手改：繁中由简中轉換而來，標題一一對應，所以用腳本按標題次序把每個 `](#简中錨點)` 換成對應的繁中錨點，再檢查一次全部存在。
5. **計劃之外補上的幾處（審閱的 low 項）：** A5 改密碼那步註明 `passwd` 會先問目前的密碼 `thinksmart`；A5 的「失敗了怎麼辦」加一條主機金鑰變了就看 3.6；简中、繁中 2.7 也說明喚醒之後用網關後台「說話語言」設的語言提問（英文版照 C15）；英文 3.3 的「正在獲取網路地址」改為介面上的英文 “Password accepted, getting a network address…”；英文附錄的「添加手機」用介面上的 “+ Add a phone”。
